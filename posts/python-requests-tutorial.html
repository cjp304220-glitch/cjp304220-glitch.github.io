Python requests: Calling APIs the Right Way

Almost every Python script eventually needs to talk to an API, and requests is the library that makes HTTP feel reasonable. Ten minutes of the right habits here saves you from scripts that hang silently at 3 a.m.

Install it (in a virtual environment)

python3 -m venv .venv
source .venv/bin/activate
pip install requests

Keeping it per-project is exactly what Python venv explained is about — do that and you never fight version conflicts again.

GET, and reading the response

import requests

r = requests.get("https://api.github.com/repos/python/cpython", timeout=10)
print(r.status_code)      # 200
print(r.headers.get("content-type"))
data = r.json()           # parsed JSON (dict/list)
print(data["full_name"])

Three rules: always pass timeout= (without it, requests waits forever), always check r.status_code or call r.raise_for_status(), and use r.json() instead of manual parsing. If the response is not JSON, r.text gives you the raw string.

Query parameters safely

params = {"q": "webrtc", "sort": "stars", "per_page": 5}
r = requests.get("https://api.github.com/search/repositories", params=params, timeout=10)
print(r.url)  # query string is built and URL-encoded for you

Never build query strings by hand with f"..." — encoding bugs (spaces, ampersands, unicode) are exactly what params handles for free. Same idea as using curl's -G --data-urlencode in the curl cheatsheet.

POST JSON

headers = {"Authorization": "Bearer TOKEN"}
payload = {"name": "naresh", "role": "developer"}

r = requests.post("https://httpbin.org/post",
                  json=payload, headers=headers, timeout=10)
print(r.status_code, r.json()["json"])

json=payload serializes the dict and sets the Content-Type header. Do not use data=payload for JSON — that sends it as a form body and the server will reject it.

Handling the ways things fail

import requests
from requests.exceptions import Timeout, ConnectionError, HTTPError

try:
    r = requests.get(url, timeout=5)
    r.raise_for_status()
except Timeout:
    print("too slow")
except HTTPError as e:
    print("server said", e.response.status_code)
except ConnectionError:
    print("network down or DNS failed")

Catch the specific exceptions, not bare Exception. A retry loop with a couple of attempts and a timeout is usually all a cron-style script needs.

Sessions for anything repeated

s = requests.Session()
s.headers.update({"Authorization": "Bearer TOKEN"})
for page in range(1, 6):
    r = s.get(API, params={"page": page}, timeout=10)
    ...

A Session reuses the TCP/TLS connection and carries cookies and default headers between calls — several times faster for loops that hit the same API. That {} in the example is only there so the f-string generator renders literal braces in the dict literal — on your screen it is a normal dict.

Cheatsheet

  • GET: requests.get(url, params=..., timeout=10)
  • POST JSON: requests.post(url, json=payload, timeout=10)
  • Auth: headers={"Authorization": "Bearer TOKEN"}
  • Check: r.raise_for_status() + r.json()
  • Never: no timeout, no status check, data= for JSON

If you outgrow polling, the next step is webhooks and background jobs — a pattern that shows up in GitHub Actions too.
