How HTTPS Works: SSL/TLS Certificates Explained

The padlock icon rests on a surprisingly simple idea: your server proves it owns the domain, then both sides negotiate a private channel. Everything else is packaging that idea securely.

What HTTPS gives you

  • Encryption — anyone watching the network sees only garbage
  • Authentication — you are talking to the real site, not an impostor
  • Integrity — the response was not altered in flight

Without HTTPS, Wi-Fi neighbours and ISPs can read and modify traffic; Chrome marks such sites "Not secure"; and some browser APIs refuse to run on HTTP at all.

The certificate in one paragraph

A certificate is a small signed file binding your domain to a public key. The signature comes from a Certificate Authority (CA) — a party browsers and operating systems already trust. When you connect, the server presents the cert, the browser checks the signature chain, the hostname match and the expiry date, and only then does the TLS handshake proceed. No valid chain, no padlock.

Getting one: free, and usually automatic

Cloudflare (what this site uses)

Point your DNS to Cloudflare and Universal SSL issues and renews certificates for you — yourdomain.com and www covered, zero clicks. The full setup is in point a domain to Cloudflare Pages.

Your own server: Let's Encrypt

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

Certbot proves domain control (usually via an HTTP challenge), fetches a cert, configures nginx, and installs a cron job to renew before the 90-day expiry. Free, automated, and what nearly every modern host does under the hood.

Certificates chained together

Your cert is not signed directly by the root CA — the root signs a few intermediates, and intermediates sign yours. Browsers ship with roots pre-trusted; servers must send the intermediate too, which is why "missing intermediate chain" is a classic first-time setup error. Managed hosts (Cloudflare, Netlify, Vercel) handle all of this invisibly.

How to check a site's cert

curl -sI https://example.com | head -5
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -dates

The openssl line prints who the cert is for and when it expires — useful before a long holiday. Or just click the padlock in the browser: it shows issuer, validity and the chain.

Common myths, quickly

  • "HTTPS slows me down" — one extra handshake, then HTTP/2 over the same connection is often faster overall
  • "I don't collect payments, so I don't need it" — authentication matters for every page, not just checkout
  • "I'll add it later" — modern tooling makes free certificates the default; adding it later is just… adding it now
