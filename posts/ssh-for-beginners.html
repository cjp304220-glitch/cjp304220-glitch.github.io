SSH for Beginners: Keys, Config and Tunnels

SSH is how you touch a server. Password login works until the internet finds it; key-based login is faster, safer, and the default expectation everywhere. Setup takes five minutes once.

Generate a key pair

ssh-keygen -t ed25519 -C "your@email.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

Accept the defaults, add a passphrase (it gets stored in your agent, so you type it once per reboot). Ed25519 is the modern choice — shorter keys, better security than old RSA defaults.

Install the public key on a server

ssh-copy-id user@yourserver.com
ssh user@yourserver.com

Second login should not ask for a password. That's it — the private key stays with you; the public key (the .pub file) is the one you hand out.

Aliases: stop typing hostnames

Create ~/.ssh/config:

Host vps
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Now ssh vps does the whole thing. Add scp file.txt vps:/tmp/ or rsync -av ./build/ vps:/var/www/ and you never type the address again.

Everyday commands

ssh vps                      # connect
scp local.txt vps:/tmp/      # copy a file there
scp vps:/var/log/app.log .   # copy a file back
rsync -avz ./src/ vps:/app/  # sync a folder efficiently
ssh vps "systemctl status nginx"   # run one command

Port forwarding: the hidden superpower

Reach a service that is not exposed to the internet through the server you can reach:

ssh -L 5432:localhost:5432 vps   # local 5432 -> server's postgres
ssh -N -f -L 8080:localhost:3000 vps

Now localhost:5432 on your machine is the database on the server. -N skips running a shell, -f backgrounds it — perfect for dev databases and internal dashboards.

Security basics that actually matter

  • Disable password login on the server once keys work: PasswordAuthentication no in sshd_config
  • Never share the private key; the .pub file is safe to post anywhere
  • Move off port 22 only if you enjoy quieter logs — keys already stop the bots
  • Add ssh-add -t 3600 policies on shared machines so keys expire

With keys and aliases in place, servers feel like folders on your machine — which is exactly the mental model that makes remote work click. The same access pattern is what deploy pipelines use under the hood, including the ones in GitHub Actions for beginners.
