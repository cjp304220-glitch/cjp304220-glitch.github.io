How to Write Prompts That Get Real Code from AI

The difference between "meh" AI output and something you can merge usually isn't the model — it's what you put in front of it. Developers who treat prompting like filing a good bug report get dramatically better code.

The structure that works

Every serious prompt has four parts:

  • Context — language, framework, versions, and how this code will be used
  • The material — the exact code, error text, schema or command that failed (paste it, do not describe it)
  • The task — one clear goal, stated once
  • The output format — what you want back: a diff, a single file, bullets of options, tests first

Weak: "my API is slow, fix it". Strong: "This is our FastAPI endpoint (paste). It does N+1 queries on Postgres 15 — rewrite it to fetch in one query, keep the response shape identical, output only the changed function, do not add dependencies".

Context is king

The assistant cannot see your repo. Paste the surrounding code that matters — the function, its caller, the type definitions. Mention versions explicitly; "React" versus "React 18 with hooks only" changes everything. If there is a house style (tabs, error conventions, no default exports), say so.

Ask for the format you want to review

Reviewing diffs is faster than reviewing blobs. Useful instructions: "show only the changed lines", "give me three options with trade-offs before coding", "write the tests first, then the implementation", "explain each step in one sentence". This also keeps answers shorter — the number one complaint about AI output.

Iterate like a reviewer, not a gambler

When output is wrong, do not immediately rewrite the whole prompt. Say what is wrong, exactly: "this assumes sync I/O but we're on asyncio" or "the variable you referenced doesn't exist in the pasted code". One round of precise feedback often fixes it — same as reviewing a junior's PR.

The trust rule

AI writes plausible code, not verified code. It invents API methods that half-exist, and it is confidently wrong at the same tone as when it is right. So: run it, read the diff, test the edge cases (empty input, unicode, concurrent calls). The prompts that help most with this end with "list the edge cases this breaks" — then you verify those first.

A reusable template

Stack: Python 3.12, FastAPI, Postgres (asyncpg)
Goal: <one sentence>
Material: <paste code / error / schema>
Constraints: no new dependencies; keep public API unchanged
Output: diff only + 3 bullet risks

Fill that in thirty seconds and you will rarely need a second attempt. If you're picking which assistant to aim this at, the comparison in ChatGPT vs Claude vs Gemini is a good starting map — and for private code, run the same template against a local model via Ollama instead.
