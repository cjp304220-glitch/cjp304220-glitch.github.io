Git and GitHub for Beginners: Clone, Commit, Push, PR

Git is your local history; GitHub is the shared copy everyone pushes to. Once that split clicks, the commands stop feeling arbitrary. This is the whole collaboration loop.

Get a project

git clone https://github.com/user/repo.git
cd repo
git status

clone copies the full history, not just files. status is the command you will run more than any other — when in doubt, ask Git what it thinks is going on.

The daily loop

git switch -c feature-short-name
# ...edit files...
git status
git add -p
git commit -m "Add rate limiting to /api/search"
git push -u origin feature-short-name

One branch per piece of work, a commit message that says why, and git add -p when you want to stage hunks instead of whole files (great for leaving debug prints unstaged). Unfamiliar with undoing commits, see revert vs reset vs restore first — it pairs with everything here.

Ignore the noise

Create .gitignore on day one:

.venv/
__pycache__/
.env
node_modules/

Secrets and dependencies should never enter history — recovering a leaked key is far more work than ignoring it.

The pull request flow

  1. Push your branch to the repo (git push -u origin branch)
  2. Open the repo on GitHub → "Compare & pull request"
  3. Fill the description: what changed and why, how you tested it
  4. Request a review; address comments with new commits on the same branch
  5. Merge (squash is the tidy default), delete the branch

If you do not have write access, fork the repo first, push to your fork, then open a PR from your fork to the original — that is the open-source contribution flow.

Keeping a branch fresh

git fetch origin
git rebase origin/main     # your commits replayed on top

Rebase gives a clean history for review; if it goes wrong, git rebase --abort is a full undo. On shared branches you have already pushed to others, prefer git merge origin/main — never rewrite published history.

Reviews: how to be good at them

  • Keep PRs small — under ~300 changed lines if you can
  • Comment on code, not people; suggest the fix, not just the problem
  • Review your own diff once before requesting review

What GitHub adds on top

Issues for work tracking, Actions for CI (see beginners' guide), and Pages for hosting — compared side by side in GitHub Pages vs Cloudflare Pages. Master clone → branch → commit → push → PR, and you can contribute to any public project on the internet.
