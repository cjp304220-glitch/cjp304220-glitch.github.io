Regular Expressions Explained Simply (Cheatsheet)

Regular expressions look like punctuation soup, but you only need about fifteen pieces to handle most real tasks: validating input, pulling data out of logs, and cleaning text. Here they are, with the recipes you will copy more than once.

The building blocks

cat       literal text: matches "cat"
.c        any character, then c: matches "cat", "cot", "c_c"
[aeiou]   one character from the set
[^aeiou]  one character NOT in the set
\d        a digit (same as [0-9])
\w        a word character: letters, digits, underscore
\s        whitespace

Uppercase versions negate: \D is a non-digit, \W a non-word character, \S non-whitespace.

How many: quantifiers

*      zero or more
+      one or more
?      zero or one (also makes things lazy)
{3}    exactly three
{2,}   two or more
{1,3}  one to three

By default quantifiers are greedy — they swallow as much as possible. Add ? to make them lazy: <.+?> matches the shortest tag, <.+> the greedy everything.

Position and structure

^        start of line (or string without multiline)
$        end of line
\b       word boundary
(colon)  capture group
(?:...)  group without capturing
a|b      either a or b
\.       literal dot (escape special characters)

The recipes

^\d{4}-\d{2}-\d{2}$          date YYYY-MM-DD
^\(?\d{3}\)?[- ]?\d{3}[- ]?\d{4}$   US phone, flexible
\b[\w.+-]+@[\w-]+\.[\w.]+\b     email-ish (see note)
\d+                                first run of digits
(?:https?://\S+)                   whole URLs
^(?!.*\bTODO\b).*$                 lines WITHOUT "TODO"

On email: perfect email validation in one regex is famously impossible. Trim, check for one @ and a dot in the domain, and validate the rest on the server — do not be a hero.

Using them day to day

grep -E '\b[0-9]{3}\b' app.log          # lines with a 3-digit number
sed -E 's/[0-9]{4}-[0-9]{2}-[0-9]{2}/DATE/g'
python3 -c 'import re,sys; print(re.findall(r"\d+", sys.stdin.read()))'

In Python, prefer raw strings (r"\d+") so backslashes stay literal, and findall for extraction, search/match for testing, sub for replacing. In logs and text pipelines, regex pairs with the pipe tricks from the Linux commands cheatsheet.

How to debug a pattern

Use regex101.com: paste your pattern, your sample text, and it highlights every match and explains each token — including a plain-English translation of your regex. Five minutes there beats an hour of guessing. When you can read a pattern token by token out loud, you are done learning regex for most jobs.
