git revert vs reset vs restore: Which One When

By Naresh · October 27, 2026 · Tutorials

On this page
  • git revert: the safe one
  • git reset: moving the branch backwards
  • git restore: fixing files, not history
  • git checkout (or switch): changing branches
  • Which one do I need?

Every Git panic follows the same pattern: you committed too early, or committed the wrong thing, and now you are staring at the terminal trying to remember whether reset or revert is the safe one. Here is the whole picture, split into the safe commands and the destructive ones.

git revert: the safe one

revert does not remove history — it creates a new commit that undoes an old one. The bad commit stays in the log, followed by its inverse. Because nothing is erased, it is the only undo that is safe on shared branches.

git revert HEAD
git revert a1b2c3d

Use it on main, on any branch other people have pulled, or whenever someone might already be built on top of the commit you want to undo.

git reset: moving the branch backwards

reset moves the branch pointer itself. Three modes, three effects:

git reset --soft HEAD~1   # commit undone, changes stay staged
git reset --mixed HEAD~1  # commit undone, changes stay in working tree (default)
git reset --hard HEAD~1   # commit, staging area and files all wiped

--hard is the dangerous one. It rewrites your working tree and uncommitted changes do not come back. Use reset on local-only branches — before you push, never after (pushing a rewritten branch needs --force and can destroy a teammate's day).

git restore: fixing files, not history

restore (Git 2.23 and newer) replaces the file-recovery half of checkout:

git restore file.py             # discard local edits to a file
git restore --staged file.py    # unstage without losing the edits

It touches the working tree and the index, never commits. When you just want one file back to its last committed state, this is the command.

git checkout (or switch): changing branches

These days checkout is mostly for branches, and Git actively suggests the dedicated commands for the other jobs:

git switch feature-x       # switch to an existing branch
git switch -c new-branch    # create and switch
git checkout -- file.py     # old-style restore, still works

Which one do I need?

  • Undo a commit I have not pushed — git reset --mixed HEAD~1 to keep changes, --hard to throw them away
  • Undo a commit already on the shared branch — git revert <commit>
  • Throw away my edits to one file — git restore file
  • Unstage but keep the edits — git restore --staged file
  • Switch what I am working on — git switch branch

Rule of thumb: history other people can see gets reverted; history that only exists on your machine can be reset; files are restored. When these commands run automatically in CI, they appear as steps in GitHub Actions for beginners.
